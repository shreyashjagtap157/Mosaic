# Release Engineering v1

Mosaic distributions are deterministic tar.gz archives with normalized timestamps/ownership. A release contains SHA-256 checksums, a release manifest, an SPDX 2.3 JSON SBOM, and an in-toto/SLSA-shaped provenance statement. The provenance records the source checksum-manifest identity and every staged artifact digest.

Cross-platform core qualification deliberately disables optional OpenSSL/ICU-dependent features so the tokenizer core proves it has no hidden dependency on them. Full Linux qualification enables all available optional trust and Unicode differential tests.

Canonical pack identity remains content-addressed and independent of the release bundle. Release provenance authenticates what was built; pack trust authenticates publisher/content relationships. These are separate security layers.

Product release artifacts use the canonical four-part `S.M.N.P` version from the repository `VERSION` file. Release qualification runs `tools/set_version.py --check` and the cross-platform source checksum validator before packaging so CMake metadata, headers, CLI tools, Python package metadata, manifests, SBOM/provenance, and archive names cannot drift independently. The consolidated local entrypoint is `tools/validate_release_readiness.py`, which chains the repository, Miri, fuzz-smoke, and release-package checks, and the release-qualification workflow now calls the same entrypoint for the Linux package gate. A faster local convenience path may skip Miri via `--skip-miri` or `make release-readiness-fast` when the long-running interpreter gate is intentionally deferred. `docs/implementation/EXTERNAL_QUALIFICATION.md` is the canonical checklist for the macOS, cargo-fuzz, race-detector, and architecture-fleet gates that still require external runners. `tools/validate_release_matrix.py` keeps the Makefile, workflow, README, and release-engineering doc aligned, while `tools/validate_open_gates.py` keeps the remaining 1.0.0 blocker summary synchronized across the candidate documentation. Pack registry SemVer and frozen ABI/format versions remain separate contracts.
The constrained-desktop evidence path is separately maintained through `tools/run_low_memory_profile.py`, the `make low-memory-profile` convenience target, and the bounded manifest example under `benches/low_memory_4gb.toml`.
